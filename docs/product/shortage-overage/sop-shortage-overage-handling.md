## Мета

Описати єдиний порядок дій для магазину, коли фактичний товар не збігається із системним залишком: є недостача, лишок або пересорт.

Дія — Результат:
- Виявили розбіжність — зафіксували факт і не виправляємо його усно.
- Перевірили пов'язані процеси — знайшли можливу причину: приймання, переміщення, пошкодження або помилка обліку.
- Ескалювали невирішений випадок — відповідальна особа приймає рішення щодо подальших дій.

## Коли застосовується

SOP застосовується, якщо в магазині виявлено:
- недостачу: товар є в системі, але фактично відсутній;
- лишок: товар фактично є, але не відображений у системі або має інший статус;
- пересорт: фактична модель, розмір, колір або кількість не збігається з документом чи системою;
- розбіжність після приймання або переміщення;
- розбіжність під час локальної перевірки залишків.

## Хто відповідальний

| Роль | Відповідальність |
|---|---|
| Співробітник, який виявив розбіжність | Не приховує випадок, повідомляє відповідального, передає первинні дані. |
| Адміністратор / КЗ | Організовує перевірку, збирає факти, контролює фіксацію. |
| Директор / керуючий | Приймає або погоджує рішення щодо закриття розбіжності. |
| Власник / уповноважена особа | Розглядає фінансово значущі або спірні випадки. |

## Покрокові дії

### 1. Зупинити довільні дії з позицією

1. Не списувати товар і не коригувати залишок без погодження.
2. Не продавати спірну позицію, якщо її статус незрозумілий.
3. Якщо товар фізично є — відкласти його до завершення перевірки.

Результат: розбіжність не маскується новими діями, а товар зберігає контрольний статус.

### 2. Зафіксувати факт розбіжності

1. Записати магазин, дату, відповідального та джерело виявлення.
2. Зафіксувати позицію: модель, розмір, колір, кількість, системний залишок і фактичну наявність.
3. Додати фото або інший доказ, якщо це потрібно для розгляду.
4. Повідомити адміністратора / КЗ.

Результат: випадок має первинну картку для розбору.

### 3. Перевірити останні пов'язані процеси

Перевірити, чи розбіжність могла виникнути через:
- незавершене або помилкове приймання;
- незакрите переміщення між магазинами;
- LIVE-переміщення або підсорт;
- пошкодження товару після приймання;
- дефект, який був виявлений під час приймання;
- технічну або облікову помилку в системі.

Результат: ймовірна причина визначена або випадок передано на ескалацію як невстановлений.

### 4. Класифікувати випадок

| Тип випадку | Ознака | Наступна дія |
|---|---|---|
| Недостача | У системі є товар, фактично немає | Перевірити приймання, переміщення, продажі, пошкодження; ескалювати. |
| Лишок | Фактично є товар, у системі немає або інший статус | Перевірити документи приймання/переміщення; не вводити довільно. |
| Пересорт | Фактична позиція не відповідає документу або системі | Звірити пов'язані позиції та джерело помилки. |
| Пошкодження | Товар є, але не може продаватися як звичайний | Діяти за регламентом пошкодження товару. |
| Дефект при прийманні | Проблему виявлено під час приймання | Діяти за регламентом виявлення браку при прийманні. |

### 5. Передати на рішення

1. Якщо причина очевидна і є погоджений порядок — передати відповідальному для закриття за процедурою.
2. Якщо причина не встановлена — ескалювати директору / керуючому.
3. Якщо випадок має фінансові наслідки або можливу матеріальну відповідальність — ескалювати власнику / уповноваженій особі.
4. Зафіксувати рішення і тільки після цього виконувати системні дії.

Результат: розбіжність закривається рішенням, а не неформальним виправленням.

### 6. Закрити випадок

1. Після погодження виконати потрібну системну дію.
2. Зберегти підтвердження рішення: документ, акт, повідомлення або інший затверджений слід.
3. Якщо причина повторюється, передати випадок на аналіз процесу.

Результат: розбіжність має закритий статус, відповідального і підтвердження рішення.

## Винятки

- Якщо розбіжність пов'язана з відключенням або збоєм системи, системні дії виконуються після відновлення доступу за погодженим порядком.
- Якщо розбіжність виникла під час переміщення, застосовується регламент переміщення товару між магазинами.
- Якщо товар пошкоджений, застосовується регламент пошкодження товару в магазині.

## Коли ескалювати

Ескалювати адміністратору / КЗ:
- будь-яку недостачу, лишок або пересорт;
- розбіжність під час приймання;
- незрозумілий статус товару після переміщення.

Ескалювати директору / керуючому:
- повторювану розбіжність;
- випадок без очевидної причини;
- незакрите переміщення, яке впливає на залишки.

Ескалювати власнику / уповноваженій особі:
- фінансово значущу розбіжність;
- можливу матеріальну відповідальність;
- спір між магазинами;
- рішення щодо списання або іншого фінального статусу товару.
